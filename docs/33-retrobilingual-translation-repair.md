## 3. 两类故障的机制

### 3.1 错字

`tools/chinese_text_recovery/decode_chinese_text.py` 用 `data/glyph_mapping.json` 把 `[G{bank}:{code}]` 换成 Unicode。映射错一个字，所有用到该字的句子一起错。`0x0003` 的「勤招」就是 `G7:19` 和 `G5:E4`。

银行 4 的常用字大部分是对的。错字集中在用得少的码位，以及少数高频但形近的字（书/中，子/土，孙/共）。

### 3.2 错页和看起来像漏译

游戏按 A 翻对话框时，运行时把 `sDlgPage` 加一。代码在上游 `core/retrobilingual.c` 的 `rb_dialogue_read()`：`render` 从 3 变成 4 时 `sDlgPage++`，再用 `(textId, sDlgPage)` 查找。

旧版抽取器曾把控制字节 `0x01` 错当成 `[WAIT]`，所以几乎不按实际次数分页。这个判断已经废弃：`0x01` 本身带一个参数；真正的换行字节是 `0x0A`。全库因此曾只有 37 个 id 有多页，一条对白的多屏内容大多堆在 `page_index == 0` 的一个字符串里。

`pack.py` 的 `split_dialogue_pages()` 在「只有第 0 页」时按另一种规则再切：每行 15 字、每两行一个新 `page_index`，行尾的 `+` 或 `@` 也会强制换页。1,473 个 id 被这样切开，pack 变成 6,082 页。这些页号不是游戏的按 A 次数。第一屏往往还像那句话的开头；再按一次 A，游戏进入下一屏，HUD 显示的是中文后半段。

查找失败时 `rb_find_dialogue_entry()` 会向更小的页回退，所以缺页显示成上一页的文字。

绘制还有第三刀。`retrobilingual_draw()` 把一行超过 15 字就折行，然后 `if (line_n > 3) line_n = 3`，多出来的行直接不画。即使 pack 里整句都在，屏幕上也只有前三行。

`decode_text()` 会删掉除玩家名以外的 `[C..]` 控制码。`0x0003` 的 `[C06:01]` 是存档编号，删掉以后「文件几」没有了。这是缺内容，不是缺整句。

不走 `gMessage` 的界面（部分菜单、地图上的短标签）本来就不在这张表里。本文不解决那些界面。

### 4.2 怎样决定一个字改不改

按出现次数从高到低看图。每个码位只做下面三种决定之一：

1. **图和现映射是同一个字**：保持。英文里的另一个词不能推翻图。`G5:7B` 是「练」就保持「练」。
2. **图明显是另一个汉字**：把 `glyph_mapping.json` 里这个键改成那个字。只改这一个键。
3. **图糊到无法分辨**：保持原映射，在报告里记 `unresolved`，并附上例句。不要用英文“猜一个更通顺的字”填进去。

优先处理第 2 节表里已看过图的 5 个候选：`G7:19`、`G5:E4`、`G4:82`、`G4:AD`、`G4:60`。打开 PNG 确认后才写入映射。然后继续处理清单里前 200 个高频码位，以及全部残留 `[G..]` 里出现超过 3 次的码位。更少的码位可以留在 `unresolved`，不要为了清零而猜。

改映射时保留 JSON 的键格式 `G10:01` 这种大写十六进制。不要改键，只改值。值必须是一个 Unicode 字符，或按钮这类已有的短占位（如现有的 `[A]`）。不要写成拼音，不要写成空字符串。

`decode_text()` 里现在的控制码处理要一起改掉，否则重解码会继续吞掉变量：

- `[C06:00]` 和 `[Player]` 继续变成 `{player}`。
- `[C06:01]` 变成 `{1}`，不要删。这是 `0x0003` 的存档号。
- `[C02:..]` 是颜色，`[C03:..]` 是声音，可以删。
- 其他还没确认的 `[C..]` 保留成原来的标记，写进报告。不要用一条正则把所有 `[C..]` 删掉。
- `[WAIT]` 可以不显示，但分页不能靠解码后的字符串恢复。阶段 2 必须回到原始字节。

`pack.py` 的 `sanitize_text()` 还有两处会破坏文本，阶段 1 先不要用它来生成审核文本：

- `t.replace("+", "。").replace("@", "？")` 会把汉化脚本里的 `+` / `@` 改成句号问号。这些字符在中文流里大量存在（约 1,730 个 `+`、353 个 `@`）。在确认它们是标点还是翻页之前，审核文本里保留原字符。
- `re.sub(r"\n+", "\n", t)` 会把空行吃掉。空行在抽取结果里可能代表换屏。阶段 1 的审核文件不要做这个折叠。

### 5.2 真正的按 A 分页（阶段 2 的后半，单独验收）

第 5.1 节让整句留在页 0，滚动才能看完。它还没有让第 N 次按 A 对上中文的第 N 屏。要做这一步，必须先证明游戏的翻页字节，不能沿用现在的两种猜测：

- 抽取器「每两个 `0x01` 算一页」没有对上运行时。证据是 3,697 个 id 里只有 37 个被分成多页，而玩家每次按 A 都会让 `sDlgPage` 增加。
- `split_dialogue_pages()` 的「两行一页」对上的是 HUD 宽度，不是日版脚本。

做法：

1. 读 zeldaret/tmc 的文本状态机（`src/text.c`、`src/message.c` 一类文件），列出每个控制字节是「当前框里的换行」还是「玩家必须按 A 才进入下一块」。把结论写成 `docs/33` 附录或单独的短注释，附上文件名和函数名。只引用结论，不要把游戏脚本文本抄进仓库。
2. 用日版 ROM 的原始字节，按这个规则把每个 `source_id` 切成盒子 0..n。用汉化 ROM 的原始字节，按同一规则切中文盒子。不要对解码后的字符串切。`decode_text()` 已经删过 `[WAIT]`。
3. 两边盒子数相同：按序号配对，中文盒子 k 写入 pack 页 k。
4. 两边盒子数不同：不要拉链配对。整段中文留在页 0，并在报告里记下这个 `source_id` 和两个长度。第 5.1 节的“只有页 0 就一直显示页 0”会接住这种情况。
5. 用 `0x1002` 做样例。写出日文盒子数、中文盒子数、每一盒的前 12 个字。执行者自己核对：第 0 盒应是招呼塞尔达公主的那一句，不能是大臣担心的那一句。对不上就不要启用新的切分，退回第 5.1 节的行为。

在第 2 步被样例证明之前，打包继续使用抽取器现成的 `(source_id, page_index)`，也就是今天这 3,749 行的页号，只是不再二次切页。

### 5.2.1 已验证的原始分页规则（2026-11-15）

已对照 zeldaret/tmc 的 `src/text.c:GetCharacter()` 与 `src/message.c`：原始 `0x0A` 产生换行命令；`RunTextCommand()` 在第二行收到该命令时进入 `RENDER_WAIT`，`TextDispWait()` 等待玩家输入，`TextDispRoll()` 随后以首行继续。因此每两个原始 `0x0A` 是一个游戏按 A 的盒子边界。`0x01` 是带参数控制码，不是边界。

按该规则重新从两份已校验 ROM 抽取：日版共 5,822 页，汉化版共 5,948 页；共有 3,592 个 `source_id` 的页数相同，105 个双方都有但页数不同的 `source_id` 采用“整段中文留页 0”的保守回退。`0x1002` 中日均为 3 页，中文页 0 以「哎! 这不是塞尔达公主吗」开头；因此允许按原始页号打包，不使用视觉拆分。

## 6. 缺页和缺字的最终表现

| 情况 | 应显示 |
|---|---|
| 精确命中当前页 | 该页中文 |
| 这个 id 只有页 0，游戏页号已经大于 0 | 页 0，左右键滚动 |
| 这个 id 有多页，但当前页不在 pack 里 | 现有的缺页条目 `source_id = FFFF`，文字「暂无翻译」 |
| 句子里仍有未映射字形 | 保持 `pending`，不要打进正式 pack。报告里留标记和 PNG 路径 |
| 菜单、地图短标签 | 不在本次范围。不要为了它们去扫别的表 |

`sanitize_text()` 里 `re.sub(r"\[[^\]]+\]", "", t)` 会把残留 `[G9:xx]` 删掉，句子出现空洞还显示成成功。正式打包必须拒绝仍含 `[G` 的条目，而不是删掉标记再收录。`{player}` 和 `{1}` 要换成可绘制的占位（「林克」和数字占位），这个替换放在确认标记已经分类之后。
