First frontend frame with the libraries served in different ways
RG SP, 2026-10-14, NextUI on TF1, second slot empty, warm restarts with USB attached.
Rootfs build v1.3.0-7-g65dd2b4 with the final rcS and boot files of this branch.

How the test works
  first-frame-test-rcS.patch is the startup script used. It samples the card's
  read counters and an MD5 of the first framebuffer every 50 ms for 11 s. The
  first frame is the first sample that differs from the boot logo. The sampler
  runs in every variant, so its own cost is the same in all of them.

  squashfs variants bind /usr/lib from a squashfs image of the final rootfs
  (LZ4 HC, 128 KiB blocks), written raw to the start of the unused slot and
  mounted through a loop device. Every file under /usr/lib in the image hashed
  the same as the file on ext4. The root itself stays ext4.

  preload variants read the 16 root-partition libraries that nextui.elf maps
  (25.0 MB, of which libmali.so.0 is 19.1 MB) with cat, in the background.

Card and root partition
  Bus mode: SD high-speed, 50 MHz, 4 bits. A raw 60 MiB read or write runs at 19.7 MB/s.
  Read-ahead window: 128 KiB. Scheduler: cfq.
  Kernel root mount (ext4, clean): 11 ms, from 1.5698 to 1.5804 s in kernel-initcalls-full.dmesg.
  At the handoff (uptime 1.34 s), three boots:
    root partition  89 requests, 3.3 MiB read, card busy 190 ms (that boot replayed the journal)
    whole card      123 to 125 requests, 3.5 to 3.7 MiB read
  Eight seconds after the handoff: 42.8 MiB read from the root partition, 11.7 MiB from the frontend card.

Squashfs images of the rootfs tree (116 MB)
  LZ4 HC, 128 KiB blocks   62,509,056 bytes
  LZ4 HC, 1 MiB blocks     61,292,544
  LZ4, 128 KiB blocks      72,028,160
  gzip, 128 KiB blocks     53,977,088
  xz, 128 KiB blocks       45,051,904

Cold read of the 16 libraries from the squashfs image, caches dropped, three runs
  730 to 750 ms, 14.3 MiB read from the card for 25.0 MB of files.
  The same test on ext4 is not valid on a running system, because the kernel
  does not drop pages that a running program has mapped. At 19.7 MB/s the
  25.0 MB would take about 1.3 s.

Seconds are kernel uptime. Reads are the whole card's, in MiB, up to the first frame.
Busy is the time the card spent on requests between the handoff and the first frame.
