/dev/input's modification time and SDL's gamepad scan, 2026-10-14

What happens
  The kernel clock counts from zero until the RTC driver sets it, late in kernel
  start-up. The input devices register before that, so /dev/input and its nodes carry
  times of a second or two after 1970-01-01 00:00:00. The directory's modification time
  is the second in which its last node appeared: 1 when that was between 1.000 and
  1.999 s of kernel time, 0 when it was earlier.

  SDL's gamepad detection without udev keeps the last modification time it saw, starting
  at 0, and scans /dev/input only when the directory's time differs. A directory time of
  0 therefore means it never scans, and the program sees no gamepad.

  Four launches of the same game in that one boot, with the directory time set by hand
  (touch -d @N /dev/input). minarch uses NextUI's libSDL2 from the frontend card and
  logs a line for the built-in gamepad it finds and skips:
    time 1   "Skipping built-in joystick 0: ANBERNIC-keys (handled via evdev)" twice   startup 905 ms
    time 0   line absent, SDL found no gamepad                                         startup 773 ms
    time 1   line logged twice again                                                   startup 948 ms
    time 0   line absent                                                               startup 683 ms
  NextUI's own log followed the same switch each time nextui.elf started.
  With the time at 0 the menu, the in-game menu and the game still took button presses:
  NextUI and minarch read the pad's event node themselves.

  The library: /mnt/sdcard/.system/h700/lib/libSDL2-2.0.so.0, 8,026,720 bytes. It has no
  reference to libudev, udev_enumerate, udev_new, udev_monitor or SDL_UDEV_Init, and it
  contains LINUX_FallbackJoystickDetect, last_input_dir_mtime, last_joy_detect_time and
  LINUX_InotifyJoystickDetect. No udev daemon runs on BaseOS. The library's source was
  not read; the behaviour above was observed.

  In the six timed boots of the game-launch test the line was absent in three (A1, A3,
  B1) and present in three. Those are the two states in game-launch-ext4-vs-image.txt.

Fix
  rcS runs "/bin/touch -c -d @1 /dev/input" right after it mounts devtmpfs. That is the
  value every 1.3.0 boot had. -c keeps touch from creating a file if the directory is
  missing. tests/test-input-dir-time.sh runs the line under BusyBox.

  With the scan back on every boot, every start of minarch again takes the 0.13 to 0.19 s
  the scan costs, as it did on release 1.3.0.

The fixed build on the RG SP
  Build 1.4.0 (v1.3.0-20-g30febbb), installed by the updater. Four restarts:
    last input device at 0.998 s   /dev/input time 1   combined 4.314 s
    last input device at 0.975 s   /dev/input time 1   combined 4.102 s
    last input device at 1.025 s   /dev/input time 1   combined 4.141 s
    last input device at 1.026 s   /dev/input time 1   combined 4.150 s
  The first two would have left the time at 0. validate-on-device.sh: 42 passed, 0 failed.
