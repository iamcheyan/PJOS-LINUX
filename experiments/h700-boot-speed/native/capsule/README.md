# Raw capsule host build

`../build.py TARGET INVENTORY NATIVE --raw-capsule` binds the canonical attempt protocol, actual capsule/build sources, inner sources, fixed layout policy and exact stock input into the native generation. Derived cookie/FNV headers and final binaries are excluded to avoid a cycle. Build the matched SPL with `../../spl/build-early-mmc.py OUTPUT --boot0 STOCK --dram --handoff-package PACKAGE --native-loader NATIVE --raw-capsule`, then run `build.py INNER_DIRECTORY STOCK NATIVE OUTPUT`. All output directories must be fresh.

The default outer builder requires the exact version2 adopt-only inner. `--diagnostic-purpose TEXT` explicitly labels a nondeployable control with a non-adopting inner; it still compiles the complete normal commit protocol and checks current generation/source pins. There is no pure dispatch or lab bypass in this builder. `verify.py OUTPUT` runs the compiled outer context/copy/MMIO fault matrix offline.

The 128KiB image reserves the first1KiB for vendor header mutations and branches to0x20400. Exact stock64KiB is at0x21000, native48KiB at0x31000, forward copy stub at0x50000, saved72-byte context at0x52000, and private stack top at0x57000. It preserves originalr0..r14/CPSR/SCTLR and transfers ROM-mutated media byte+0x28 into the selected inner header. Entry requires little-endian A32SVC and SCTLRM/C/I clear; V is preserved and no vector is used. No SCR/MVBAR/RMR transition occurs in the outer.

Resume retention1f8bit16 and any nonzero owned pair select stock before any RTC/watchdog write. Normal empty-pair boot verifies both payloads, arms/readbacks watchdog, then commits cookie and pending with fences/readbacks before copying native. The inner validates exactpair/config1/modeb1 before clocks and again beforeMMC; it performs no RTC/config/mode/media writes or old journal/source/resume operations. Checkpoints remain inRAM. Existing final owned watchdog reload is retained after another exact adoption check.

Every manifest remains hardware_qualified=false and durable_install_eligible=false. Host proofs do not establish watchdog survival across nativeRMR3, real warm/BROM capsule loading, cache/security/selector state, early-refusal recovery, recoveryTOC updater suppression, or installation/torn-primary safety. Strict adoption must not run on hardware until the independent pre-own-arm watchdog retention control passes: a failed check with a lost watchdog can otherwise wait without recovery.
