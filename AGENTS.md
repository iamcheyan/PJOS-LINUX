## PocketShell launcher development and simulator

- The canonical launcher source is the separate checkout `~/development/pocketshell`; this repository supplies the BaseOS image, frontend script, library scanner and runtime patches. The launcher is a PocketJS Solid/TSX application; its compiled package is `~/development/pocketshell/dist/pocketshell.pocket`. The image's currently bundled launcher is `overlay/usr/share/pocketshell/System/pocketjs/apps/boot.pocket`. Editing one checkout does not automatically update the other or a device. Preserve existing uncommitted work in both repositories.
- Current redesign targets a 480 × 320 logical viewport and a 720 × 480 panel. `app/pocket.json` and `config/profile.ts` in PocketShell define the package profile; the current UI uses a 240 × 160 layout subtree scaled 2× within that viewport. CPU presentation requires the targeted 1.5× path in `src/apply-pocketjs-fractional-display.py`; an unpatched CPU runtime rejects this geometry. The patch uses nearest-neighbor sampling, caches the logical raster while its draw list and resource revision are unchanged, and still presents a full output frame. Device performance and visual output remain unverified.
- The new package profile has a different admission hash from older 240 × 160 packages. Keep the old runtime at `System/pocketjs/bin/pocket-linux-kms` for existing apps; the updated frontend searches `System/pocketjs/bin/launcher/pocket-linux-kms` first, then the old binary, and chooses the runtime that admits each package. Both binaries retain the same basename for hotkey process matching. `build-rootfs.sh` rejects debug runtimes and checks the bundled launcher against the new runtime before installing it under `/usr/share/baseos/pocketjs/launcher/`; `frontend-session` atomically copies it to the corresponding card directory while preserving the legacy runtime. QEMU checks confirmed the legacy runtime admits the original package and the new runtime rejects that old profile. Do not overwrite the old runtime with the new profile or assume old applications can run on it. Verify runtime selection, fallback package admission and installed apps on the device before deployment acceptance.
- Build the launcher with `cd ~/development/pocketshell && make build`. The default SDK is `~/development/.pocketjs-star-drift-sdk` and Bun is `~/.bun/bin/bun`. The build stages files under the SDK's `apps/pocketshell` and `programs/pocketshell`; `scripts/build.sh` also applies the PJOS OSK theme patch to the SDK. Treat the SDK as a shared, potentially modified working tree and do not reset or clean it.
- `scripts/stage-library-glyphs.ts` generates a common simplified Chinese and Japanese kana glyph set in the staged app for library titles. This is baked font coverage, not unlimited Unicode streaming; verify glyphs and package memory on the target. Build and desktop staging both invoke it, and the generated file is not a hand-maintained source asset. The initial build with this set was approximately 11.2 MB and completed a three-frame GNU/QEMU smoke test; a desktop fixture also rendered `魔女的冒险`. Target memory and startup time remain unmeasured. Desktop and device build scripts now select the same Fusion Pixel primary font.
- Export the matching runtime profile after a launcher build: `cd ~/development/.pocketjs-star-drift-sdk && ~/.bun/bin/bun tools/pocket.ts profile export --config programs/pocketshell/pocket.runtime-config.ts --out ~/development/PJOS-LINUX/work/runtime-profile`. Compare its profile hash with `bun tools/pocket-pack.ts inspect ~/development/pocketshell/dist/pocketshell.pocket` before building or deploying a runtime.
- The local cross build is `cd ~/development/PJOS-LINUX && PJOS_RUNTIME_SOURCE="$PWD/work/runtime-source" PJOS_PROFILE_RS="$PWD/work/runtime-profile/pocket_profile.rs" sh ./build-pocketjs-runtime-local.sh`. It writes `work/pocketjs-runtime/pocket-linux-kms`; its GNU static binary was tested under QEMU, but is not the preferred BaseOS device binary. The device build uses `PJOS_ROCKNIX_TREE="$HOME/.cache/pjs-rt/tree" sh ./build-pocketjs-runtime-musl.sh`, Docker, the pinned ROCKNIX source tarball and bridge scripts. Both build scripts apply cover, favorites and fractional-display patches. The musl build and its device admission must be verified; output of either build shares the same path, so identify which binary is present before copying it.
- QEMU smoke test for a matching AArch64 runtime and launcher package: `qemu-aarch64 work/pocketjs-runtime/pocket-linux-kms --package ~/development/pocketshell/dist/pocketshell.pocket --headless --frames 3`. A successful run prints `completed 3 logical ticks; 720x480`; this proves admission and frame execution, not visual fidelity or device performance. For the fractional renderer test, copy `tests/pocket-fractional-render.rs` into `work/runtime-local/src/engine/raster/tests/pjos_fractional.rs` after the runtime staging build, then run `cargo test --offline --manifest-path work/runtime-local/src/Cargo.toml -p pocket-raster --test pjos_fractional`.
- For an isolated captured software framebuffer, the local build accepts `PJOS_RUNTIME_DEBUG=1 PJOS_RUNTIME_OUTPUT=/tmp/pjos-cached-debug/pocket-linux-kms`; this debug-only build adds `PJOS_TEST_LIBRARY` fixture input and writes raw BGRX pixels on exit when `PJOS_HEADLESS_CAPTURE` names a file. For example: `PJOS_TEST_LIBRARY=/tmp/pocketshell-library-chinese.json PJOS_HEADLESS_CAPTURE=/tmp/pjos-frame-720.raw qemu-aarch64 /tmp/pjos-cached-debug/pocket-linux-kms --package ~/development/pocketshell/dist/pocketshell.pocket --headless --frames 30`, then verify the raw file is 1,382,400 bytes and decode with `convert -size 720x480 -depth 8 bgra:/tmp/pjos-frame-720.raw /tmp/pjos-headless-720.png`. Set `PJOS_TEST_BUTTON=right` to inject one right-button press during the debug run. The fixture-backed `docs/evidence/2026-11-13-pocketshell/qemu-launcher-720.png` and `qemu-after-right-720.png` show the centered cover, title and background before and after the press; package SHA-256 was `bfd8cbde70a8bb80cdce829b2bc51ecaff9df474f6638b36442e9ce3a5d3a393`. Never use the debug binary as the production device runtime. The normal musl build does not apply this debug patch.
- The desktop simulator is PocketJS's real desktop host, not `app/browser-preview.html`. `~/development/pocketshell/scripts/desktop-local.sh` stages and compiles the current app, patches the SDK's desktop bridge and host, builds `/tmp/pocketshell-desktop/program`, and starts the window. Its `grim` screenshot captures the entire desktop, so it is not by itself evidence of the launcher window. Its bridge patch requires the sibling `PJOS-LINUX` checkout and exposes fixture input only when the following environment variables are explicitly set.
- Isolated X11 example, from PocketShell, with a temporary X server (choose an unused display):
  ```sh
  Xvfb :94 -screen 0 720x540x24 -nolisten tcp &
  env -u WAYLAND_DISPLAY DISPLAY=:94 WINIT_UNIX_BACKEND=x11 \
    POCKETSHELL_TEST_LIBRARY="$PWD/tests/fixtures/launcher-library.json" \
    POCKETSHELL_TEST_FAVORITES=/tmp/pocketshell-favorites-test.txt \
    POCKETJS_SDK="$HOME/development/.pocketjs-star-drift-sdk" \
    ./scripts/desktop-local.sh --no-shot
  DISPLAY=:94 xwininfo -root -tree
  DISPLAY=:94 import -window <launcher-window-id> /tmp/pocketshell-window.png
  convert /tmp/pocketshell-window.png -filter point -resize 720x480 /tmp/pocketshell-720.png
  ```
  Stop only the Xvfb/launcher processes started for the test. The desktop window is 480 × 320; the resized image illustrates target dimensions but is not a framebuffer capture. For reliable simulated keyboard input, focus the launcher and hold a key briefly, e.g. `DISPLAY=:94 xdotool windowfocus <launcher-window-id> keydown Right; sleep 0.25; DISPLAY=:94 xdotool keyup Right`. Desktop mappings include `Space` for START, `x` for A/confirm, `z` for B/back, and `q`/`w` for category shoulders. Keep temporary fixture favorites isolated from real user data.
- To test background changes, create a temporary copy of `tests/fixtures/launcher-library.json` with different absolute PNG/JPEG `cover` paths in its game items and pass it as `POCKETSHELL_TEST_LIBRARY`; the committed fixture intentionally contains only example ROM paths. The BaseOS scanner adds `cover` metadata for same-name image files alongside a ROM or in `images`/`downloaded_images`. `frontend-session` prefers the card scanner when it reports `cover-v1` from `capabilities`; otherwise it uses the image scanner if available, so an older card copy cannot silently discard cover metadata. `COVER` bridge decoding produces cached rounded square textures and blurred backgrounds; `FAVORITES` persists paths under `/storage/.config/pocketjs/favorites.txt`. Empty or missing covers use existing fallback artwork.
- The current launcher exposes `.gba`, `.gb` and `.gbc` ROMs, including uppercase extensions, because these are the formats supported by the bundled player and handoff scripts. The scanner also indexes other systems for other consumers; do not advertise them as launchable in PocketShell until their player path is implemented and verified. Distinct ROM paths are retained even when their titles match.
- Relevant checks: `cd ~/development/pocketshell && ~/.bun/bin/bun test tests`; in this repository run `python3 tests/test-game-cover-scan.py`, `python3 tests/test-favorites-bridge.py`, `python3 tests/test-runtime-selection.py` and `sh -n overlay/usr/share/pocketshell/System/launch_frontend.sh`. `python3 tests/test-headless-launch.py` uses the debug runtime to inject A/confirm and verifies the selected fixture ROM path reaches a mocked launch bridge; it skips when the debug runtime or QEMU is absent. These are focused checks, not a substitute for testing game launch, menu, favorites, category changes and framebuffer output on hardware.
- Device deployment helpers in the PocketShell checkout now use `scripts/deploy-rg34xx.sh`: `make check` stages the matched package and runtime and performs admission without replacing installed files; `make deploy` backs up existing card files, installs the new runtime alongside the legacy runtime and replaces the launcher, scanner and player shims transactionally. It prefers a single online local ADB device (`PJOS_ADB_SERIAL` selects one); if unavailable, set `PJOS_DEVICE_IP` and `PJOS_DEV_PW` for the documented password-assisted SSH transport. It checks hostname/root identity, stages SHA-256 manifests, verifies runtime admission, backs up under `/storage/System/pocketjs/backups`, restarts only after successful installation, and captures the active framebuffer page without `exec-out`. `scripts/deploy-ssh.sh` forces the SSH path. `python3 tests/test-install-rg34xx.py` exercises backup/rollback and ADB exit-status handling on a fake tree, and `python3 tests/test-deploy-check.py` stages the real package/runtime through mock ADB and checks admission under QEMU. These helpers have not yet been exercised on the handheld; inspect their output and the captured PNG, and do not report a deployment successful merely because staging passed.
- As of this redesign, QEMU has run 720 × 480 ticks with matching GNU and musl runtimes and the fractional pixel mapping test passed. Desktop simulation displayed the carousel, cover-derived background and a background change between two fixture covers; `Space` then `x` added a fixture game, and the favorites category and removal were verified against an isolated favorites file. Shoulder-key navigation also displayed the settings and system pages with the shared status bar and footer. Actual device deployment, full image build, 1.5× performance, all hardware input paths and full visual parity are still pending. Rebuild the launcher after source changes, and do not treat an old `dist` artifact or desktop screenshot as proof of the latest code.

## RG34XX test device

- Device: BaseOS RG34XX, hostname `rg34xx`.
- Wi-Fi SSH: `root@<device-lan-ip>`, port `22`.
- The development image uses a fixed throwaway password; it is not recorded in this repository.
- Prefer USB ADB when connected: run `adb devices -l`, then `adb -s <device-serial> shell 'hostname; id'`. Use the password-assisted Wi-Fi SSH command below if the USB transport is absent/offline or intentionally disabled. Do not stop diagnosis at an empty ADB list.
- Example: `ssh root@<device-lan-ip>`.
- Verified noninteractive login (2026-11-12):
  ```sh
  sshpass -p "$PJOS_DEV_PW" ssh -o ConnectTimeout=5 -o UserKnownHostsFile=/tmp/pjos-debug-known-hosts -o StrictHostKeyChecking=accept-new root@<device-lan-ip> 'hostname; id'
  ```
  Expected output includes `rg34xx` and `uid=0(root)`. A bare `ssh` command does not supply the documented password automatically; use `sshpass` for noninteractive tools. Do not use `BatchMode=yes` for password login.
- Verified USB ADB on 2026-11-12 after manual `usb-gadget-adb setup` recovery: Debian sees serial `<device-serial>` as `device`, the handheld returns `rg34xx`/`uid=0(root)`, UDC state is `configured`, and `g1/UDC` contains `5100000.udc-controller`. The previously observed empty UDC was a gadget binding/OTG state issue, not proof that `adbd` was dead.
- ADB is USB-only: no TCP listener on port 5555 is expected. `/data/no-adb` is its persistent opt-out. The new `usb-gadget-adb status` reports requested `on`/`off`; `enable` clears the opt-out and actively retries setup every time, even if already enabled; `disable` persists the opt-out and removes the ADB interface while preserving any already selected storage function. Settings route through `rocknix-services set adbusb.enabled on|off`. Never test the off path through the sole active ADB transport: establish SSH first.
- Source now includes `/sbin/hotplug` (installed from `overlay/usr/sbin/hotplug` via merged-/usr). After initial boot setup, it retries a lost binding on a power-supply/UDC event only when ADB is enabled, the existing composition contains ADB, USB power is online, and safely read `usbc0/otg_role` is `usb_device`. It does not force a role or run a resident polling watcher. A host-role attach remains a vendor-kernel limitation; use enable to request setup, and if necessary boot with the data cable attached. Do not read the role-trigger siblings `usb_device`, `usb_host`, or `usb_null`.
- Hotplug/off→on behavior is covered by fake-tree tests. The scripts are now deployed, and software disable→enable was verified over backup SSH: ADB disappeared while off and reappeared as `device` after enabling and waiting for host enumeration. Real cable replug and UI switch-cycle verification remain separate pending checks. See `docs/24-rg34xx-adb-recovery.md` and the unified issue tracker `docs/25-rg34xx-debug-progress.md`.
 - Debugged SSH and ADB using the exact verified password-assisted SSH command above. Do not use bare SSH with `BatchMode=yes` or conclude SSH is unavailable without testing the documented command.
- An old host key for this IP exists in the default known_hosts. The working command isolates the current device key in `/tmp/pjos-debug-known-hosts`, preserving existing records. `accept-new` records a first-seen key; it does not independently verify its identity or accept a changed key in that file. The device ED25519 fingerprint observed during this session was `SHA256:gvXjj5OSbV/V+FjbNyWb+wGefuxeStGAvuhZA7CdysI`.
- The SD card's active System directory is `/mnt/sdcard/System`, also accessible as `/storage/System`.
- Runtime settings: `/storage/.config/pocketjs/runtime.conf`.
- Idle policy overrides: `/storage/.config/baseos/screen-idle.conf`. These override the launcher settings; check both files when debugging sleep or automatic power-off.
- During the current investigation, automatic screen blanking and power-off were temporarily disabled with `timeout = never` and `auto_stop_timeout = never` in the idle override file. Do not report this mitigation as a completed fix.
- Framebuffer: `/dev/fb0` is a 720 × 960 double-height buffer, 32 bits per pixel/BGRX; the visible panel is 720 × 480. Read `/sys/class/graphics/fb0/pan` for the active offset (observed `0,480`) and crop that 720 × 480 region after decoding. The other half can contain an old game's frame; do not mistake both buffers for a split-screen UI. With this adbd, use `adb shell 'dd if=/dev/fb0 of=/tmp/frame.raw bs=4096 count=675'` then `adb pull`; `exec-out` is unsupported. Check the raw file is 2,764,800 bytes before decoding.
- USB identity: `18d1:4e42` (serial kept out of the repo). The PVE host is reachable from the lab; the Debian VM there has `usb0: host=18d1:4e42` configured.
- Back up device files before deploying changes and verify the active files and device behavior after deployment. Do not disable Wi-Fi while it is the active debugging transport.
